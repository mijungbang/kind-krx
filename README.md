## 1. 개요

한국거래소(KRX) KIND 시스템에서 다음과 같은 **시장조치 공시**를 수집합니다:

| 구분 | 내용 |
| --- | --- |
| 거래정지/재개 | 매매거래 정지, 재개, 단기과열완화장치 발동 등 |
| 관리종목 | 관리종목 지정/해제 |
| 투자주의환기 | 투자주의환기종목 지정/해제 |
| 투자경고·위험 | 투자경고종목 지정/재지정/해제, 투자위험종목 지정/해제 |
| 단기과열 | 단기과열종목 지정/해제/예고 |
| 기타 시장안내 | 기타 시장 관련 안내 |
| 상장폐지 | 상장폐지 결정/사유 등 |

수집된 공시는 **넥스트레이드(NXT)** 등록 종목과 **종목코드 기준으로 매핑**되어,
NXT 거래 대상 종목에 해당하는 공시만 별도 탭에서 확인할 수 있습니다.

## 4. 메뉴 구성

사이드바 라디오 버튼으로 카테고리를 선택합니다.

| 키 | 라벨 | 수집 소스 | 요청 수 |
| --- | --- | --- | --- |
| `multi` | ✅ NXT종목 모아보기 | 아래 전체 통합 | 42 |
| `halt` | 1️⃣ 거래정지/재개 종목 | cat(`0311`) + market_watch | 24 |
| `mgmt` | 2️⃣ 관리종목 | cat(`0350`) | 1 |
| `alert` | 3️⃣ 투자주의환기 종목 | cat(`0356`) | 1 |
| `inv` | 4️⃣ 투자경고·위험 종목 | warn payload (12 reportCd) | 12 |
| `overheat` | 5️⃣ 단기과열 종목 | warn payload (`reportNm="단기과열"`) | 1 |
| `misc` | 6️⃣ 기타 시장안내 | cat(`0305`) | 1 |
| `delist` | ⚠️ 상장폐지 | warn payload (2 reportCd) | 2 |

> 요청 수는 각 소스가 1페이지로 끝나는 경우 기준입니다. 결과가 100건을 넘으면 페이지네이션으로 늘어납니다.

### 소스 정의 방식

메뉴별 수집 대상은 `menu2.py`의 `_source_specs()` / `MENU_SOURCES` 두 곳으로 통합되어 있습니다.

```python
MENU_SOURCES = {
    "multi": ["halt_cat", "mw", "mgmt", "alert", "misc", "inv", "overheat", "delist"],
    "halt":  ["halt_cat", "mw"],
    "mgmt":  ["mgmt"],
    ...
}
```

`_fetch()`는 이 목록을 순회하며 소스를 하나씩 수집한 뒤 병합합니다.
**소스 하나가 실패해도 나머지는 그대로 살아남고**, 실패 내역만 별도로 표시됩니다.
전부 실패했을 때만 예외를 올립니다.

## 5. 데이터 수집 방식

KIND에서 공시를 수집하는 방식은 **두 가지**로 나뉩니다.

### 5-1. 카테고리 기반 (cat)

KIND의 **상세검색 → 카테고리(disclosureType02)** 를 이용합니다.

```
POST https://kind.krx.co.kr/disclosure/details.do
disclosureType02 = "0311|"   ← 카테고리 코드
fromDate / toDate            ← 조회 기간
```

사용 메뉴: `halt`, `mgmt`, `alert`, `misc`

코드 매핑 (`CODE_MAP`):

| 키 | 코드 | 의미 |
| --- | --- | --- |
| `halt` | `0311` | 거래정지/재개 |
| `mgmt` | `0350` | 관리종목 |
| `alert` | `0356` | 투자주의·환기 |
| `misc` | `0305` | 기타 시장안내 |

### 5-2. reportCd 기반 (warn payload)

KIND의 **제목검색(reportNm) + reportCd** 조합을 이용합니다.
카테고리 코드 없이, `bfrDsclsType=on`이 포함된 페이로드를 사용합니다.

```
POST https://kind.krx.co.kr/disclosure/details.do
reportNm = "투자경고종목지정"
reportCd = "68809"
bfrDsclsType = "on"
```

사용 메뉴: `inv`, `overheat`, `delist`, 그리고 `halt`에 병합되는 `market_watch`

## 6. 네트워크 계층 — 세션·페이싱·병렬 수집

KIND는 브라우저 사용을 전제로 만든 화면이라, 단순 POST만 반복하면 쉽게 차단(403)됩니다.
`fnc2.py`는 아래 네 가지로 대응합니다.

### 6-1. 전역 세션 재사용 + GET 워밍업

요청마다 세션을 새로 만들면 `JSESSIONID` 쿠키가 없는 상태로 POST가 나가고, TCP/TLS 핸드셰이크도 매번 반복됩니다.

```
GET  /main.do?method=loadInitPage          ← 쿠키 발급
GET  /disclosure/details.do?method=...     ← Referer 체인 형성
POST /disclosure/details.do                ← 실제 조회 (이후 keep-alive 재사용)
```

세션은 모듈 전역으로 하나만 유지되며, `HTTPAdapter(pool_maxsize=MAX_INFLIGHT)`로 커넥션 풀 크기를 동시 요청 수에 맞춰뒀습니다.

### 6-2. 적응형 페이싱 (`_Pacer`)

**정상일 때는 거의 쉬지 않고, 저항이 감지될 때만 느려집니다.**

| 상황 | 요청 간격 |
| --- | --- |
| 평상시 | `PACE_FLOOR` (0.05초) |
| 403/429/503 최초 발생 | `PACE_FIRST` (2초) |
| 연속 실패 | 2배씩 증가, `PACE_CEILING`(30초)까지 |
| 이후 성공 `PACE_RECOVER_AFTER`(4)회마다 | 절반으로 감소 → 평상시로 복귀 |

`threading.Lock`으로 보호되어 병렬 요청 환경에서도 간격이 정확히 유지됩니다.

### 6-3. 병렬 수집

reportCd 목록은 `ThreadPoolExecutor`로 동시에 수집합니다.
HTTP 요청은 대부분 응답 대기 시간이고, 파이썬은 I/O 대기 중 GIL을 놓기 때문에 스레드로 효과적으로 겹칩니다.

| 소스 | 순차 (요청당 0.4초 가정) | 병렬 |
| --- | --- | --- |
| 시장감시위원회 (23) | 9.2초 | **1.8초** |
| 투자경고·위험 (12) | 4.8초 | **1.1초** |

동시 요청 수는 `MAX_INFLIGHT`(기본 6) 세마포어가 **전역으로** 제한합니다.
스레드풀 크기와 무관하게 실제로 날아가는 요청은 항상 6개 이하입니다.
403이 발생하면 페이서가 간격을 벌리므로, 병렬 상태에서도 자동으로 직렬에 가깝게 느려집니다.

> 페이지네이션은 병렬화하지 않습니다. 다음 페이지가 존재하는지는 현재 페이지 응답을 봐야 알 수 있기 때문입니다.

### 6-4. 재시도 + 세션 세대(generation)

403/429/503 또는 "정상 테이블 아님" 응답이면 최대 4회까지 재시도합니다(백오프 4s → 8s → 16s).
재시도 시 세션을 새로 발급받는데, 여러 스레드가 동시에 403을 맞아도 **세션은 한 번만 재생성**됩니다.

```python
s, gen = get_session(stale_gen=stale_gen)  # "내가 쓰던 세대가 아직 현역일 때만" 재생성
```

세대 번호가 이미 바뀌었다면 다른 스레드가 먼저 갱신한 것이므로 그 세션을 그대로 씁니다.

## 7. NXT 종목 매핑

### 매핑 방식: 종목코드 기준

```
NXT  원본:    A005680  (7자리, isuSrdCd)
       ↓  fnc.py에서 str[1:] 처리
NXT  단축코드: 005680   (6자리)
       ↓  menu2.py에서 str[:5] 처리
매핑키:       00568    (5자리)

KIND 종목코드: 00568    (5자리, 마지막 체크디짓 누락)
```

```python
nxt_df["_code5"] = nxt_df["단축코드"].astype(str).str[:5]
nxt_codes = set(nxt_df["_code5"]) - {""}
df_nxt_trade = df_all_show[df_all_show["종목코드"].isin(nxt_codes)]
```

## 8. UI 기능 상세

### 사이드바

| 영역 | 설명 |
| --- | --- |
| 📆 KIND 조회 기간 | 시작일/종료일 선택 (기본: 최근 5일) |
| ⚠️ KIND 시장조치 공시 | 카테고리 라디오 버튼 (8개 메뉴) |
| 🔎 제목/종목/시간 검색 | 키워드 필터 (공시제목 + 종목명, 대소문자 무시) |
| 조회 시간 | 시작/종료 시간 프리셋 (00:00~23:59, 14:28~14:31 등) |
| 체크박스 | 단기과열 `(예고)` 공시 제외 옵션 (메뉴별 조건부 표시) |
| 버튼 | 공시 조회 / 🔄 강제 새로조회 / 🧹 초기화 |

- **🔄 강제 새로조회**: 캐시 nonce 증가 + `fnc2.reset_session()` 호출 후 **자동으로 재조회**합니다. 403 이후에는 세션이 오염돼 있을 가능성이 높아 둘을 함께 처리합니다.
- **🧹 초기화**: 세션 리셋 + `st.cache_data.clear()` + `st.session_state.clear()`

### 진행률 카드 (`ProgressUI`)

조회 중에는 소스별 상태를 실시간 체크리스트로 표시합니다.

```
수집 중                              15/42 · 6s
━━━━━━━━━━━━━━━━━━━━━░░░░░░░░░░░░░░░░░░░
● 거래정지/재개 (카테고리)              12건
● 시장감시위원회                      14/23
○ 관리종목
○ 투자경고·위험
● 상장폐지                            실패
```

- 진행률은 소스 개수가 아니라 **요청 수** 기준이라, 23개짜리 소스에서도 막대가 계속 움직입니다.
- 상태 점: 대기(회색) / 진행(파랑, 깜빡임) / 완료(초록) / 실패(빨강)
- 완료된 소스는 수집 건수를, 진행 중인 소스는 `14/23`을 뱃지로 표시합니다.
- 색상을 `rgba` 기반으로 지정해 다크 모드에서도 깨지지 않습니다.

## 13. 캐시 및 세션 관리

| 메커니즘 | 설명 |
| --- | --- |
| `@st.cache_data(ttl=60)` | `_fetch()`에 적용. 동일 (메뉴, 시작일, 종료일, nonce) 조합은 60초간 캐시 |
| `st.session_state["menu_cache"]` | 조회 결과를 세션에 저장. 메뉴/기간 전환 시 재활용 |
| `st.session_state["force_nonce"]` | 🔄 강제 새로조회 시 nonce 증가 → 캐시 키 변경으로 강제 재수집 |
| `fnc2` 전역 세션 | 모듈 수준에서 유지. `reset_session()`으로만 파기 |

`_fetch()`의 `_ui` 인자는 언더스코어로 시작해 `st.cache_data`의 해싱 대상에서 제외됩니다.
캐시 히트 시에는 진행률 카드가 표시되지 않고 즉시 결과가 나옵니다.

### 캐시 키 구조

```
cache_key = (menu_key, from_date_str, to_date_str)
# 예: ("multi", "2026-07-25", "2026-07-31")
```

키워드 필터와 시간 필터는 캐시된 원본 데이터에 대해 **클라이언트 측에서만** 적용되므로,
필터를 변경해도 KIND에 재요청하지 않습니다.

## 14. 에러 핸들링

### 부분 실패 허용

소스 8개 중 일부만 실패하면 **나머지 결과는 그대로 표시**하고 경고만 띄웁니다.

```
⚠️ 2개 소스 수집에 실패해 결과가 불완전합니다.
  ▸ 실패 상세
      시장감시위원회 → [99457] 장애종목매매거래정지...: KIND 요청 실패(재시도 4회). 마지막 오류: HTTP 403
      상장폐지: KIND 요청 실패(재시도 4회). 마지막 오류: HTTP 403
```

reportCd 단위 실패는 `df.attrs["kind_errors"]`에 담겨 전달되며, `_fetch()`가 이를 수집해 UI로 올립니다.
**전부 실패했을 때만** 예외를 올려 에러 화면으로 빠집니다.

### KIND 차단/비정상 응답 감지

```python
def _looks_like_valid_kind_table(html: str) -> bool:
    return 'list type-00 mt10' in html
```

KIND가 200 OK를 반환하지만 실제 테이블이 없는 경우(IP 차단, 세션 만료, 점검 등)도
실패로 간주해 재시도 대상에 포함합니다.

### 403 전용 안내

에러 메시지에 `403`이 포함되면 IP 차단 가능성을 안내합니다. 403은 대기 시간을 늘려도
해결되지 않는 경우가 대부분이라, 잘못된 방향으로 시간을 쓰지 않도록 구분했습니다.

### NXT 조회 실패 시 Fallback

```python
try:
    from fnc import get_nextrade_filtered_symbols
except Exception:
    def get_nextrade_filtered_symbols(yyyymmdd):
        return yyyymmdd, pd.DataFrame(columns=["종목명"])
```

`fnc.py`가 없거나 import 실패 시에도 앱은 정상 동작하며, "NXT 종목 정보를 가져오지 못했습니다" 안내가 표시됩니다.

## 16. 트러블슈팅

### 403 Forbidden이 계속 나올 때

`fnc2.diagnose()`로 어느 단계에서 막히는지 확인합니다.

```bash
python -c "import fnc2, json; print(json.dumps(fnc2.diagnose(), ensure_ascii=False, indent=2))"
```

| 결과 | 해석 | 대응 |
| --- | --- | --- |
| `main_get` / `details_get`이 이미 403 | IP 차단 | 코드로 해결 불가 → 호스팅 이전 |
| GET은 200인데 `details_post`만 403 | 세션/헤더 문제 | 🔄 강제 새로조회, `MAX_INFLIGHT` 낮추기 |
| `data_krx_get`도 403 | KRX 전체가 해당 IP 차단 | `fnc.py`도 곧 실패 → 호스팅 이전 |
| `cookies`가 비어 있음 | `JSESSIONID` 발급 실패 | 워밍업 단계부터 차단 → 호스팅 이전 |

### IP 차단인 경우

Streamlit Community Cloud는 AWS 미국 IP를 사용하며, KRX 계열 서비스는 해외/데이터센터 IP를 차단하는 경우가 많습니다. 국내 리전으로 옮기는 것이 근본적인 해결책입니다.

- **Oracle Cloud Always Free** — 춘천/서울 리전, ARM 인스턴스 무료
- **NHN Cloud / 네이버 클라우드 / 카페24** — 국내 IP, 소형 인스턴스 저렴
- **집 PC나 NAS + Cloudflare Tunnel** — 개인용이면 가장 간단

리포지토리에 `Dockerfile`이 포함되어 있어 컨테이너로 바로 옮길 수 있습니다.

### 조회가 느릴 때

`pacer_status()`의 `delay`가 `PACE_FLOOR`보다 크면 차단 감지로 속도를 낮춘 상태입니다.
앱에서도 지연이 2초를 넘으면 안내 메시지가 표시됩니다. 연속 성공하면 자동으로 회복됩니다.

## 17. 주의사항

- **KIND 차단**: 병렬 요청은 순차보다 WAF 눈에 띄기 쉽습니다. 차단이 늘면 `MAX_INFLIGHT`를 먼저 낮추세요.
- **조회 부담**: 모아보기는 최소 42회 요청이 발생합니다. 실시간 모니터링이 목적이라면 조회 기간을 1~2일로 줄이고 폴링 주기를 늘리는 편이 안정적입니다.
- **SSL 인증서**: `verify=False`로 설정되어 있어 SSL 검증을 건너뜁니다. 운영 환경에서는 인증서 설정을 검토하세요.
- **종목코드 5자리**: KIND HTML 파싱 특성상 마지막 체크디짓이 누락됩니다. 외부 시스템 연동 시 주의가 필요합니다.
